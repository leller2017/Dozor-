# Дозор

Android-приложение, которое превращает телефон в сторожа для системы видеонаблюдения.
Телефон смотрит на монитор с камерами. Если картинка меняется, приложение сохраняет серию снимков и подаёт громкий сигнал.

## Как собрать APK

### Вариант 1. Android Studio (проще всего)
1. Установите [Android Studio](https://developer.android.com/studio) (Koala или новее).
2. `File → Open` → выберите папку `Dozor`. Дождитесь окончания синхронизации Gradle: в первый раз она скачает SDK и библиотеки, это займёт 5–15 минут.
3. `Build → Build App Bundle(s) / APK(s) → Build APK(s)`.
4. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`. Скопируйте его на телефон и установите (понадобится разрешить установку из неизвестных источников).

Можно и без копирования файла: подключите телефон по USB с включённой отладкой и нажмите ▶ Run.

### Вариант 2. GitHub Actions (без установки чего-либо)
Залейте папку в репозиторий на GitHub. Workflow `.github/workflows/build.yml` сам прогонит тесты и соберёт APK.
Результат появится во вкладке **Actions → последний запуск → Artifacts → dozor-apk**.

### Вариант 3. Командная строка
Нужны JDK 17 и Android SDK (переменная `ANDROID_HOME` или файл `local.properties`).
```
./gradlew assembleDebug
```

## Как пользоваться
1. Поставьте телефон на подставку напротив монитора и наведите камеру так, чтобы окна камер занимали почти весь кадр.
2. Нажмите **«Начать дежурство»**. Первые 2–3 секунды камера подстраивает экспозицию: в это время тревоги не срабатывают.
3. Экран телефона можно выключить, анализ продолжится. Телефон лучше держать на зарядке.
4. При срабатывании приложение сохраняет 3–5 снимков с меткой времени, включает сирену через поток будильника и показывает полноэкранную тревогу.
5. **Журнал**: список срабатываний с миниатюрами. Тап открывает полные снимки (листаются свайпом, можно поделиться), долгий тап удаляет запись.

### Советы по настройке
- Ложные тревоги от мерцания монитора: увеличьте «кадров подряд» до 4–5 или снизьте чувствительность.
- Пропускает мелкое движение: поднимите чувствительность и наведите камеру ближе.
- В настройках включите **«Не ограничивать в фоне»**. Некоторые прошивки (Xiaomi, Huawei, Samsung) без этого останавливают фоновую работу ночью.
- Android 14+: разрешите **«Тревога поверх экрана блокировки»**, иначе вместо полноэкранной тревоги придёт обычное уведомление.

## Что реализовано (по ТЗ)
| Пункт | Где в коде |
|---|---|
| Дежурный режим: кнопки, индикатор, счётчик | `ui/MainActivity.kt`, `service/WatchState.kt` |
| Кадры через CameraX, 2–5 кадров/с | `service/WatchService.kt` (`analyze`), `camera/FrameUtils.kt` |
| Сравнение соседних кадров, порог по доле пикселей | `detection/MotionDetector.kt` |
| Защита от мерцания: компенсация яркости, фильтр шума, N кадров подряд | `detection/MotionDetector.kt` |
| Серия из 3–5 снимков с меткой времени | `camera/ShotWriter.kt` |
| Громкий звук и уведомление при выключенном экране | `alert/AlarmPlayer.kt`, `alert/Notifications.kt`, `ui/AlarmActivity.kt` |
| Анти-спам: не чаще раза в N секунд | `WatchService.analyze` (cooldown) |
| Журнал с миниатюрами и полными снимками | `data/EventRepository.kt`, `ui/JournalActivity.kt`, `ui/EventActivity.kt` |
| Настройки: чувствительность, интервал, звук, тихие часы | `ui/SettingsActivity.kt`, `data/SettingsRepository.kt` |
| Foreground service (тип camera), работа с выключенным экраном | `WatchService` + partial wake lock |
| Камера занята другим приложением | `WatchService.onCameraState`, `MainActivity.onPreviewCameraState` |
| Штатный запрос разрешений | `MainActivity` (камера, уведомления, полноэкранные уведомления) |

**Звук.** По умолчанию играет встроенная сирена (`res/raw/siren.wav`). В настройках можно выбрать любой системный звук будильника или уведомления. Сигнал идёт через поток будильника, поэтому его слышно и в беззвучном режиме. Опционально громкость поднимается до максимума, а после сигнала возвращается прежняя.

**Тихие часы.** В это время срабатывания записываются в журнал и приходит уведомление без звука.

**Снимки** хранятся в памяти телефона: `Android/data/ru.dozor.app/files/Pictures/events/<дата_время>/`.

## Архитектура
```
ui/          экраны (Activity + View, без лишних фреймворков)
service/     WatchService — камера + анализ; WatchState — общее состояние (StateFlow)
camera/      преобразование кадров, сохранение снимков
detection/   Detector (интерфейс) + MotionDetector (разница кадров)
alert/       звук, уведомления, «Заглушить»
data/        настройки (SharedPreferences), журнал (папки на диске)
publish/     EventPublisher — точка расширения для облака и push
```

Сервис не знает, кому сообщать о тревоге: он вызывает список `EventPublisher` из `DozorApp`. Сейчас там два получателя: локальная тревога и заглушка `CloudUploader.Disabled`.

## Планы развития
- **Отличать человека от тени.** Добавить второй `Detector`, например TFLite / ML Kit Object Detection. Он запускается только на кадрах, где `MotionDetector` уже увидел изменение, поэтому батарея почти не страдает.
- **Облако.** Реализовать `CloudUploader.onEventComplete`: задача WorkManager выгружает `event.shots` в Firebase Storage, Яндекс Object Storage или S3.
- **Удалённые уведомления.** `PushNotifier : EventPublisher` отправляет событие через FCM или Telegram-бота на телефон хозяина.
- Зоны детекции (выделить на кадре только нужные окна камер), ночной режим автоэкспозиции, экспорт журнала.

## Параметры детектора
Ползунок чувствительности 0–100 переводится в два порога:
- порог изменения яркости пикселя: от 45 до 10 (из 255);
- доля изменившейся площади: от 6 % до 0,2 % (меняется по экспоненте).

Анализ идёт на уменьшенной сетке примерно 96×54 с усреднением. Так гасится шум матрицы и муар от пикселей монитора. Из разницы вычитается её среднее, поэтому равномерные изменения яркости (мерцание, автоэкспозиция) не считаются движением.
